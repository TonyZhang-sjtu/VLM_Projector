# 第二台服务器：同步 64× 与 BindFormer 更新

以下内容可以直接交给目标服务器上的代码助手执行。发布 commit 使用源服务器最终回复给出的 SHA；仓库为 `https://github.com/TonyZhang-sjtu/VLM_Projector.git`，分支为 `main`。

请完成本机代码同步、CPU 回归、64× 真实配置预检，以及有空闲 GPU 时的短步真实模型训练和 checkpoint 重载验证。先验证跑通，完成后汇报；本次不启动正式长训练。

1. **保留本机配置和任务。** 找到本机现有仓库，记录 `git status --short --untracked-files=all`、当前分支和 HEAD。审阅工作区差异，将本地代码修改备份到仓库外，必要时做有名字的选择性 stash。记录并备份本机 `configs/local_paths.yaml`（或 `PROJECTOR_LOCAL_CONFIG` 指定文件）、其 SHA256、Python/Conda 路径、GPU 设置、`PROJECTOR_OUTPUT_ROOT`。保留本机数据、模型、缓存、知识库、评测资产和已有 run；不要复制源服务器的 `/mnt/sda/...` 路径，不要使用 `reset --hard`、`clean`、强制覆盖或停止其他任务。若正在运行的任务稍后还会加载同仓库源码，先用独立 checkout 验证，避免热更新干扰任务。

2. **同步并核对版本。** 在已保存本地修改后执行：

   ```bash
   git fetch origin main
   git pull --ff-only origin main
   git rev-parse HEAD
   # 把下面的值替换成源服务器给出的发布 SHA。
   RELEASE_COMMIT=源服务器提供的SHA
   git merge-base --is-ancestor "$RELEASE_COMMIT" HEAD
   ```

   如果不能快进，先审阅分叉并保留本地修改后合并，不要强行重置。恢复本机修改时逐项审阅，不要把旧实现整体盖回新代码。再次比较路径配置的 SHA256，并确认仍被 `git check-ignore` 忽略。

   本次 E1–E6 / N1–N6 入口移到 `scripts/ft_ablation/Exp1018/`。新路由入口在 `scripts/ft_ablation/Exp1020/`。role-value-adapter 保留既有目录布局，Git 仅新增追踪 `results/BindFormer_role_value_adapter_r16/` 下 `_launch.bash`、`entry.py`、`runtime.py`、`reader_adapter.py` 四份运行源码；其他文件和子目录仍被忽略。如果目标机已有同名未追踪源码，先备份、比较再处理 pull 冲突，不要删除实验结果。

3. **使用本机环境和路径。** 激活已有 projector 环境，再设置：

   ```bash
   export PROJECTOR_PYTHON="$(command -v python)"
   export PROJECTOR_LOCAL_CONFIG="${PROJECTOR_LOCAL_CONFIG:-$PWD/configs/local_paths.yaml}"
   export PYTHONNOUSERSITE=1
   export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2
   test -x "$PROJECTOR_PYTHON"
   test -f "$PROJECTOR_LOCAL_CONFIG"
   git check-ignore "$PROJECTOR_LOCAL_CONFIG"
   "$PROJECTOR_PYTHON" -c 'import sys, torch; print(sys.executable); print(torch.__version__)'
   ```

   外置配置不在仓库内时，`git check-ignore` 不适用，核对它没有进入 Git 即可。不要自动重建或升级已有环境。必要时参考 `docs/ENVIRONMENT_AND_MIGRATION.md`。

   检查本机 data root、annotation root、manifest、encoder、decoder、预处理缓存及输出根目录。旧 `scripts/baselines/run_*.sh` 的路径配置要显式传 `--config "$PROJECTOR_LOCAL_CONFIG"`；新的 constant-LR 入口会自动加载它，也接受同样的显式参数。GPU 编号按本机选择，外部 `CUDA_VISIBLE_DEVICES` 覆盖脚本默认值，程序内用逻辑 `cuda:0`。

   BindFormer 的正式配置还需要本机知识库 `assets/knowledge/bindformer_brain_candidates_v2`，或在本地 overlay 中设置 `projector.params.concept_bank` 指向本机已有库。核对 `embedding_manifest.json`、对应张量及校验信息和 `brats_train` 范围；资产不从 Git 下载。缺少知识库时继续完成 baseline 验证，并明确报告 BindFormer 的资产缺口，不要把 `knowledge_mode=none` 当成正式配置通过。完整临床评测资产同样留在本机。

   ```bash
     tests/test_bindformer_role_value_adapter.py \
     tests/test_ft_ablation_launchers.py tests/test_n_experiments.py
   ```

5. **保存 64× 的真实配置 dry-run。** 在仓库内创建一个唯一的、Git 忽略的验证目录。下例 `CUDA_VISIBLE_DEVICES=0` 仅用于满足入口格式要求，`--dry-run` 不加载模型或占用 GPU；正式 GPU 验证前必须重新选择空闲卡。

   ```bash
   export SYNC64_CHECK_DIR="$PWD/.tmp/server2_sync64_$(date -u +%Y%m%dT%H%M%S%NZ)"
   mkdir -p "$SYNC64_CHECK_DIR"
   CUDA_VISIBLE_DEVICES=0 bash scripts/ft_ablation/run_avgpool3d_constant_lr.sh \
     --config "$PROJECTOR_LOCAL_CONFIG" --ratios 64 --dry-run \
     --output-root "$SYNC64_CHECK_DIR/planned_runs" --run-tag avgpool64 \
     > "$SYNC64_CHECK_DIR/avgpool64.json"
   CUDA_VISIBLE_DEVICES=0 bash scripts/ft_ablation/Exp1020/run_bindformer_va_fixed_region_adaptive_constlr.sh \
     --config "$PROJECTOR_LOCAL_CONFIG" --ratios 64 --dry-run \
     --output-root "$SYNC64_CHECK_DIR/planned_runs" --run-tag bindformer64 \
     > "$SYNC64_CHECK_DIR/bindformer64.json"
   CUDA_VISIBLE_DEVICES=0 bash scripts/ft_ablation/Exp1020/run_bindformer_va_fixed_region_adaptive_role_value_adapter_constlr.sh \
     --config "$PROJECTOR_LOCAL_CONFIG" --ratios 64 --dry-run \
     --output-root "$SYNC64_CHECK_DIR/planned_runs" --run-tag adapter64 \
     > "$SYNC64_CHECK_DIR/adapter64.json"
   ```

   同样预检准备运行的其他 baseline，可直接给各入口加 `--ratios 64`，无需修改脚本默认数组。支持原始 4/8/16/32 档与新增 64 档，MLP 只支持 1×。

   核对 `ratios=[64]`、train/val/test=1960/268/560、full test、`best.pt`、配置中的本机路径和样本身份。样本数量一致不等于数据划分相同。BraTS 输入网格应为 `[39,15,15]`，物理范围 `[156,240,240]` mm；实际预算如下，不要强行把所有方法改成同一个 token 数：

   | 方法 | 64× 目标下实际 token | 实际压缩比 |
   | --- | ---: | ---: |
   | AvgPool / ConvPool / Mixer / LocalPacker | 144，网格 `[4,6,6]` | 60.938× |
   | Concat | 140，块 `[6,3,4]` | 62.679× |
   | BindFormer / AttentionPool / Perceiver / AdaptiveMerge / TokenSelect | 138 | 63.587× |

   BindFormer 默认是 34 global + 26 slots × 4 roles。不同输入几何若触发预设校验，应调查输入配置，不要绕过检查。role-value-adapter 计划中的训练、评测命令都必须经过其 `entry.py`，以保证 checkpoint 重载使用相同实现。

6. **在空闲 GPU 上验证真实运行。** 用 `nvidia-smi` 核对卡号和占用；保留其他任务。无空闲卡则明确标记 GPU 验证待完成。选定一张空闲卡后设置 `CUDA_VISIBLE_DEVICES` 为本机物理编号，再运行：

   ```bash
   CUBLAS_WORKSPACE_CONFIG=:4096:8 PROJECTOR_TEST_DEVICE=cuda:0 \
     "$PROJECTOR_PYTHON" -m pytest -q tests/test_ratio64.py -k cuda_full_width
   ```

   然后从上面的 dry-run JSON 各复制一份 config，先验证 AvgPool64，再验证准备使用的 BindFormer64 / adapter64。用独立目录运行 6 个 optimizer updates、2 条 validation，不运行 sweep 的完整 test 阶段。下面只生成 smoke 配置，不启动训练：

   ```bash
   "$PROJECTOR_PYTHON" - <<'PY'
   import json, os
   from pathlib import Path
   from omegaconf import OmegaConf
   root = Path(os.environ['SYNC64_CHECK_DIR'])
   for name in ('avgpool64', 'bindformer64', 'adapter64'):
       plan = json.loads((root / f'{name}.json').read_text())
       config = OmegaConf.create(plan['runs'][0]['config'])
       config.training.run_dir = str(root / name / 'joint_lora')
       for key, value in dict(max_epochs=1, max_steps=6, train_limit=6, val_limit=2,
                              effective_batch_size=1, microbatch_per_device=1,
                              projector_warmup_steps=2, projector_hold_steps=0,
                              joint_warmup_steps=2, checkpoint_epochs=[],
                              validation_generation_samples=0,
                              early_stopping_enabled=False).items():
           config.training[key] = value
       OmegaConf.save(config, root / f'{name}_smoke.yaml')
   PY
   ```

   普通 AvgPool / BindFormer 用 `"$PROJECTOR_PYTHON" -m src.cli.train --config "$SYNC64_CHECK_DIR/avgpool64_smoke.yaml"`（另一组替换配置名）。adapter 必须用 `"$PROJECTOR_PYTHON" results/BindFormer_role_value_adapter_r16/entry.py src.cli.train --config "$SYNC64_CHECK_DIR/adapter64_smoke.yaml"`。可先分别加 `--dry-run` 检查 2+2+2 的短步日程，再实际执行；保存输出日志。

   对每组新生成的 `joint_lora/checkpoints/best.pt` 做一次新进程重载评测：普通方法使用 `-m src.cli.evaluate_checkpoint`，adapter 使用 `results/BindFormer_role_value_adapter_r16/entry.py src.cli.evaluate_checkpoint`，参数为：

   ```text
   --checkpoint <该组新建的best.pt>
   --output-dir <该组新的smoke_eval目录>
   --split val --limit 2 --device cuda:0
   --metrics answer_ce bleu4 rougeL --repeats 0
   ```

   核对 loss/梯度有限、实际 visual tokens 分别为 144/138、LoRA 联合阶段完成、`training_state.json` 为 6 步完成、checkpoint 能重载、两条验证样本生成与指标成功。短测不是正式结果，也不代表完整 test 或所有临床指标已验证；正式训练入口仍使用原训练参数和完整 test/all 指标协议。

7. **最终汇报。** 给出实际 HEAD、发布 SHA 是否包含、本机路径配置前后是否一致、CPU/GPU 测试数量、各方法 64× 预算、dry-run 和 smoke 目录、checkpoint 重载及指标结果、缺失资产或其他阻塞。最后列出本机可直接执行的 64× 正式启动命令，保留原参数，仅按本机需要覆盖 GPU、路径、run tag 和 `--ratios 64`；暂不启动正式长训练。
